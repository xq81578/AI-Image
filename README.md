# 时光对照创作工具

## Codex 自动出片入口

新增 `$time-echo-video` 技能：由 Codex 策划、调用内置生图、实际看图审核，不合格定向返工或自动换题，使用本机音乐与 FFmpeg 输出一条视频。这条流程不读取网页 API 配置、不调用北海等模型 API，不需要 API Key。

在本项目的 Codex 任务中输入“使用 $time-echo-video 生成一条视频”即可运行。技能源码位于 [skills/time-echo-video/SKILL.md](skills/time-echo-video/SKILL.md)，本地助手为 `codex_video.py`。助手负责文件、进度、次数上限和视频合成，生图及主观质量判断由 Codex 完成；单独双击 Python 脚本不会启动智能体生图。

每轮随机 5 或 6 组，成片 20 或 24 秒，旧照在上、今照在下、带年份、1080×1920、30fps，沿用 4 秒/组和 0.6 秒转场。今照保留识别地点的主要结构，允许红纸、招牌、装修、设施与用途消失或更新；审核会拒绝“只是人少了，十年前的细节原封不动”的画面。情绪来自生活的缺席，也可以来自翻新后的陌生感。

结果保存在 `outputs/codex-time-echo/<批次>/时光对照.mp4`。批次保存选题、完整提示词、逐张审核及生成进度；中断后恢复原批次，成片后默认清理本轮工作素材，保留轻量预览和记录。内置生图工具本身的原始文件不会被删除。`codex-video.json` 可设置新批次的保留素材开关和次数上限：默认每张 3 次、每组 3 个选题、整轮 36 次调用；不会通过反复新建批次绕过上限。

制作任务以输出目录的 `execution.json` 记录整轮执行者和凭证，跨对话保留占用。A 执行时 B 启动会返回 `busy`，不能修改原批进度或另建批次；占用不按等待时长过期。A 正常结束或暂停后 `release`；异常中断未释放时，由 Codex 状态工具核实原任务已停止，再按 `skills/time-echo-video/references/execution.md` 接管。无法确认停止时保留占用。接管保留制作进度并使原执行凭证失效；后续修改命令必须带 `--token`。首次启用前需停止仍使用旧版脚本的执行任务。

时间与间隔由用户自行决定，当前不预设或启用定时任务。配置 Codex 定时任务时，在本机项目中使用 [定时任务提示词](skills/time-echo-video/schedule-prompt.md)，并确保已安装本技能。电脑需开机联网、Codex 可运行、内置生图工具与额度可用；首次定时运行仍需验证其工具可用性。限流和错误会保存断点并报告，不自动切换 API。一个项目只启用一个出片定时任务，避免多轮同时占用同一批素材。

新增验证：`python -m unittest discover -s tests -p test_codex_video.py -v`。完整项目验证命令见下方。

2026-09-12 已完成一次真实手动试跑：10 次内置生图调用，5 组对照，20 秒配乐视频，逐张审图、首尾及转场抽帧检查通过；全片解码无黑屏，音轨有有效音量。定时任务尚未启用，其运行环境内的工具可用性需要在首次定时执行时验证。

## 原有网页入口

双击 `启动创作工具.vbs`，选择成品视频目录，配置已有文本/生图服务，填写目标合图数量后点击“一键生成视频”。`启动创作工具.bat` 可用于查看启动错误。

重复双击启动器会复用默认端口上的本机服务，新启动的检查进程随后退出，只重新打开网页。关闭网页后本机服务仍会保留。更新网页文件后刷新页面即可；更新 `server.py` 后需要重启本机服务，重复双击不会自动替换正在运行的 Python 代码。

每组依次完成灵感、提示词、旧照、今照、本地合成和素材准备；各组并行推进。全部合图就绪后，按组编号制作一条 1080×1920、30fps 的 MP4，默认每张 4 秒，淡入淡出转场 0.6 秒。6 组合图对应约 24 秒视频。旧照在上、今照在下，合图仅叠加年份（例如“2001年”“2026年”），视频直接沿用。合成、加字、配乐、视频编码均在本机完成，不调用模型。

“同时保存合图”默认关闭：只向所选目录保存 MP4；成功后删除本机临时图片以及浏览器内的原图、合图和图片预览缓存，保留轻量的年份、提示词、配文和成品路径。开启时会另外保存每组带年份的 PNG。失败或停止视频制作时暂留素材，便于直接重试视频；主动放弃并新建批次也会清理该批临时素材，已保存文件保留。

将音乐放入项目 `bgm` 目录即可使用，支持 MP3、M4A、WAV、AAC、FLAC、OGG。每批开始时重新扫描并随机选一首，后续添加音乐会自动进入候选；本批重试保持原曲。音乐短了循环、长了截断。开始前检查视频环境、音乐和输出目录，避免生成图片后才发现视频无法制作。

- 旧年份从 2000 年开始随机，以十年以上跨度为主；新年份为运行当年或前一年。每组年份确定后，重试不会改变。
- 旧照是手持纸质照片翻拍，彩照为主、少量黑白，做旧程度匹配保存年限；现在图引用旧照内部场景，直接呈现手机拍摄的现实画面。
- 并发数量在“并发与重试”中设置，仍受服务商额度与限流约束。临时接口错误最多自动重试 2 次，其余错误可手动重试。
- 暂停只停止后续步骤，已经发出的请求会继续接收结果。单组暂停不会影响其他组，整批恢复也不会解除单组暂停。
- 在详情中可查看原图、合图、提示词和配文。暂停一组并等待当前请求结束后，可以编辑提示词；修改旧照会重做两张图，修改今照会保留旧照。
- 合成或素材准备失败会保留已有图片，重试只处理失败步骤。某组暂停或失败时，视频等待该组处理；明确点击“放弃此组并排除视频”后才会跳过该组。
- 视频有独立进度和“停止视频制作”“重试视频制作”按钮。停止后再次制作会从视频编码开始，保留照片和原配乐，不重新调用模型。不会覆盖已有同名文件；视频成功前只写临时文件。
- 最近一批未完成任务和图片缓存在当前浏览器，本机视频任务也会记录状态。重新打开页面可恢复已完成步骤；中断且未收到结果的模型请求需手动重试。页面关闭不终止已经启动的视频制作；若此时视频完成，下次打开页面会补做浏览器图片缓存清理。清除浏览器网站数据会清除未完成任务的浏览器缓存，已保存文件不受影响。

“本地流程演示”使用带演示标识的本地图形，并实际生成配乐 MP4，方便检查流程、图片开关和保存目录，不调用付费模型。正式创作请选择对应生图服务。

本机服务仅监听回环地址，负责目录选择、公开图片下载、临时素材、图片保存和视频制作；制片时临时启动 FFmpeg，不增加常驻 Python 服务。默认仍打开原 `index.html` 文件位置，沿用该浏览器原有模型配置。请继续使用原浏览器；换浏览器或改为 HTTP 地址打开，配置与任务缓存属于不同存储位置。API Key 仍由页面直接发给配置的模型服务，不写入任务缓存或本机服务日志。

运行环境：Windows、`C:\Python313\pythonw.exe`（及同目录 `python.exe`）、Pillow、FFmpeg 和 FFprobe。当前机器已具备。启动器使用脚本所在目录，可处理中文路径。

视频工具优先使用本项目 `tools/ffmpeg.exe` 和 `tools/ffprobe.exe`。当前为 9.0.1 essentials，来源为 FFmpeg 官网链接的 [Gyan.dev Windows builds](https://www.gyan.dev/ffmpeg/builds/)，下载 ZIP 的 SHA-256 已核对为 `fec81ae03971d9dd4be3ebe02e263bd2ec1d789483f931bdba5f5715e65da2e9`。`tools/` 二进制、`bgm/` 音乐和 `.video-cache/` 临时素材不提交 Git；迁移项目时需另行带上工具和音乐。

## Telegram 通知与视频号交付

新增独立技能 `skills/telegram-notify`，个人安装位置为 `C:/Users/Administrator/.codex/skills/telegram-notify`。通过专用 Telegram 机器人给本人发送任务完成、卡点、图片和 MP4，可供其他已授权任务复用。首次使用需在 @BotFather 创建机器人，运行技能脚本的 `setup-gui` 在本机输入 Token，再通过 `bind-start` 链接和 `bind-poll` 绑定本人私聊。Token 使用 Windows DPAPI 加密保存在 `%LOCALAPPDATA%/CodexNotifications/telegram`，不写入仓库或聊天记录。

通知使用 Telegram 官方 Bot API，不使用模型 API。成功回执去重，结果不确定时不自动重发；通知失败不会导致重新出片。技能需由正在运行的 Codex 调用，不是常驻监控，不能在电脑关机或 Codex 完全无法运行时保证提醒。机器人回复尚未接入遥控或自动恢复。

时光对照技能出片后准备本轮 `publish-info.json` 和 `发布文案.txt`，发送通知与视频。发布设置沿用用户截图：不显示位置、合集“旧时光”、无链接、不参与活动、不定时、原创意图、视频标注“内容为虚构剧情，仅供娱乐”。发布阶段执行固定脚本 `C:/Python313/python.exe publish_video.py --run <批次> --token <执行凭证>`：脚本通过 `打开视频号.bat` 启动独立 Edge，落到 `login.html` 时截取微信 OAuth iframe 中的二维码并通过 Telegram 发送，登录成功后自动上传、填表、登记提交意图并只点击一次“发表”。正常流程不依赖 Codex逐项操作网页。依赖使用 `C:/Python313/python.exe -m pip install -r requirements-publish.txt` 安装；`publish_video.py --probe` 只检查连接和页面，`--dry-run` 会上传填表但不点击“发表”。独立 `publish-progress.json` 记录登录、上传、提交、结果与通知交付进度；提交结果不明时脚本进入 `uncertain` 并禁止重复发表。登录页二维码和已登录发表页的控件结构均已实测，实际视频上传与发表未在只读校准中执行。详细流程见 `skills/time-echo-video/references/publishing.md`。
