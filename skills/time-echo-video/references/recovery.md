# 整轮失败后的恢复守护

本说明只处理 Codex 整个执行轮次因模型容量、宿主瞬时错误或应用重启而结束的情况。Python 脚本不能重启模型轮次；它只保存批次、执行权和 `pending` 请求。

## 何时建立

- 用户手动要求执行完整出片流程时，在 `begin` 之前使用 Codex `automation_update` 为当前任务创建一个临时 heartbeat，每 5 分钟唤醒一次，通知策略设为仅失败时通知。
- 名称使用 `时光对照恢复-<当前任务 ID 后 8 位>`，先检查同名自动化；存在则更新或启用，不能重复创建。
- 当前轮本身由 heartbeat 唤醒，或由已有周期出片自动化运行时，不再创建嵌套 heartbeat。周期出片提示词负责在下一次运行时恢复未完成批次。
- 建立守护失败不阻止出片，但要在本任务中说明此次仍需人工 Retry 才能从整轮失败恢复。

heartbeat 的用户可见提示词应清楚表达以下目标，不写原始调度表达式：

> 继续当前任务尚未完成的时光对照视频。读取 `$time-echo-video` 和项目约定，先检查当前批次执行权与状态。若本任务仍持有执行权，从原批次继续；遇到 `pending` 时优先找回上一轮已经返回的图片工具结果，不重复生图。若制作、通知和发布已经完成，或已经保存需要用户处理的明确阻塞，保持安静并停用本恢复 heartbeat。不得创建并行批次，不得重复发布。

## 唤醒后的判断

1. 先执行只读的 `ownership` 和 `status`。当前任务仍持有执行权时，从 `ownership` 取回原 `run_id` 与 `token`，用带 token 的 `begin` 继续；不要接管自己，也不要创建新批次。
2. 若当前任务的另一轮仍在运行或工具尚未返回，保持安静并结束本次 heartbeat，不发起并行调用。任务状态无法确认时同样不推进。
3. 遇到 `pending`，检查上一轮对应的 `imageGeneration` 工具结果：
   - 已返回本地图片路径：查看图片、完成审核并对原 attempt 执行 `record`。
   - 工具明确报错且没有图片：对原 attempt 执行 `fail`，再按失败类型决定重试、阻塞或等待。
   - 结果仍在运行、未知或存在多个无法对应的候选：不执行 `fail`，也不再次生图，保留现场等待下一次唤醒或用户核实。
4. `Selected model is at capacity` 属于执行层临时失败。heartbeat 只在后续唤醒时继续原状态，不把它记成图片审核失败，不更换题目，也不重置调用预算。

## 何时停用

- 发布成功且通知状态为 delivered 后，先 `release`，再把临时 heartbeat 设为暂停；不要删除周期出片自动化。
- 已保存明确阻塞并通知用户、需要登录或需要人工核对 `UNCERTAIN_SUBMISSION` 时，释放执行权后暂停临时 heartbeat，避免持续打扰或重复提交。
- 若本轮没有成功创建临时 heartbeat，不执行虚假的停用步骤。
- 停用操作失败时只报告自动化名称与失败原因；视频、通知或平台发布不得因此重做。
