# 整轮失败后的恢复守护

本说明处理 Codex 统筹轮次因模型容量、宿主瞬时错误或应用重启而结束的情况，也处理同一批次制作子智能体的中断。Python 脚本不能重启模型轮次；它只保存批次、`manifest.json` 中各 `pairs[i].worker` 委派登记、`execution.json` 中的统筹执行权和 `pending` 请求。父统筹中断不等于已授权子智能体停止，恢复前必须逐个核实。

## 何时建立

- 用户手动要求执行完整出片流程时，在 `begin` 之前使用 Codex `automation_update` 为当前任务创建一个临时 heartbeat，每 5 分钟唤醒一次，通知策略设为仅失败时通知。
- 名称使用 `时光对照恢复-<当前任务 ID 后 8 位>`，先检查同名自动化；存在则更新或启用，不能重复创建。
- 当前轮本身由 heartbeat 唤醒，或由已有周期出片自动化运行时，不再创建嵌套 heartbeat。周期出片提示词负责在下一次运行时恢复未完成批次。
- 建立守护失败不阻止出片，但要在本任务中说明此次仍需人工 Retry 才能从整轮失败恢复。

heartbeat 的用户可见提示词应清楚表达以下目标，不写原始调度表达式：

> 继续当前任务尚未完成的时光对照视频。读取 `$time-echo-video` 和项目约定，先检查当前批次统筹执行权、委派登记和状态。若本任务仍持有执行权，从原批次继续；遇到 `pending` 时优先找回统筹或已登记子智能体上一轮已经返回的图片工具结果，不重复生图。逐个核对已登记子智能体的真实状态；父统筹中断不代表子已停止。若制作、通知和发布已经完成，或已经保存需要用户处理的明确阻塞，保持安静并停用本恢复 heartbeat。不得创建并行批次，不得重复发布。

## 唤醒后的判断

1. 先执行只读的 `ownership` 和 `status`，并读取委派登记。当前统筹仍持有执行权时，从 `ownership` 取回原 `run_id` 与统筹 token，用带 token 的 `begin` 继续；不要接管自己，也不要创建新批次。子智能体不执行 `begin`、`takeover` 或 `release`。
2. 若当前统筹或任一已登记子智能体仍在运行、等待工具或状态无法确认，保持安静并结束本次 heartbeat，不发起并行调用，不接管，不因记录陈旧判断已停止。
3. 遇到 `pending`，按 `manifest.json` 的 `pairs[i].worker` 委派记录定位到对应的统筹或子智能体，并检查上一轮对应的 `imageGeneration` 工具结果：
   - 已返回本地图片路径：由当前统筹使用自己的有效统筹 token 查看图片、完成审核并对原 attempt 执行 `record`；子智能体 token 失效或不可唤醒时也必须先走这一步。
   - 工具明确报错且没有图片：对原 attempt 执行 `fail`，再按失败类型决定重试、阻塞或等待。
   - 结果仍在运行、未知或存在多个无法对应的候选：不执行 `fail`，也不再次生图，保留现场等待下一次唤醒或用户核实。
4. `Selected model is at capacity` 属于执行层临时失败。heartbeat 只在后续唤醒时继续原状态，不把它记成图片审核失败，不更换题目，也不重置调用预算。

## 委派子智能体恢复

- 委派记录保存在 `manifest.json` 的 `pairs[i].worker`，必须保留每个 `run`、`pair`、子智能体真实 `CODEX_THREAD_ID`、canonical agent name、独立 token 和状态；统筹占用才保存在 `execution.json`。先恢复或等待已有子智能体及其实际工具结果，再决定是否重新委派未完成组；已合格旧照、今照和审核记录直接复用。
- `takeover` 前必须用 Codex `wait_threads`（必要时 `read_thread`）核实统筹及所有已授权子智能体都已空闲、完成或中断，且没有仍运行的工具。只有全部满足才写带完整 `workers` 映射的核验文件并接管；旧授权在成功接管后全部失效，重新委派时为未完成组取得新 token。
- 任何未登记的工具结果先找回并与原 `attempt` 对应，再由当前统筹使用有效统筹 token 决定 `record` 或 `fail`；不能因为父轮次中断就重复生图，也不能先换 worker 再登记旧结果。若存在多个无法对应的结果，保持 pending 并报告，等待核实。
- 原 worker 已确认停止且本组无 pending 时，才创建替代 worker；替代 worker 先报告真实 ID 和 `image_gen` 可用性，再在同一统筹代际使用 `delegate --file <旧worker停止核验JSON>` 旋转组 token。成功 takeover 后，接管核验已覆盖旧 worker 停止，新统筹对无 pending 的未完成组创建替代 worker、等待 ready 后直接 delegate，再发送开工任务。
- 本地文件锁短暂 `busy` 且 `execution` 为空，视为写竞争：对完全相同的本地命令做有限重试，不新增 `attempt`、不再次调用生图。只有确认真实持有者冲突才停止；不得删除锁文件或改写 `execution.json` 抢占。
- 没有 `pairs[i].worker` 的旧批次，先由统筹处理原 pending 并复用已合格素材，再为所有未完成组按 [组间并发制作](parallel.md) 建立委派；不要为补建记录重做图片、另建批次或默认退回串行。

## 何时停用

- 统筹确认所有组已完成或已保存明确阻塞，且发布成功并通知状态为 delivered 后，先由统筹 `release`，再把临时 heartbeat 设为暂停；不要删除周期出片自动化。子智能体不执行 `release`，也不建立或停用 heartbeat。
- 已保存明确阻塞并通知用户、需要登录或需要人工核对 `UNCERTAIN_SUBMISSION` 时，释放执行权后暂停临时 heartbeat，避免持续打扰或重复提交。
- 若本轮没有成功创建临时 heartbeat，不执行虚假的停用步骤。
- 停用操作失败时只报告自动化名称与失败原因；视频、通知或平台发布不得因此重做。
