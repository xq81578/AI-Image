# 成品交付与视频号发布信息

本项目用户已同意当前采用：自动出片、准备发布资料、Telegram 通知，用户手动发布视频号。
浏览器曾明确以站点安全策略拒绝 `https://channels.weixin.qq.com/login.html`，并禁止换浏览器、原始 CDP、命令或间接请求绕过。本机完全权限不代表该限制解除。当前流程不访问该站点，也不承诺获取登录二维码或自动发表。通知能力不会改变来源页面的访问权限。

## 完成后交付

`finish` 成功后，在**该批次目录**准备 `publish-info.json` 与便于复制的 `发布文案.txt`。根据本轮实际选题写短标题、描述和话题，不每轮机械复用同一文案。不把 AI 场景描述成真实历史纪实照片，不编造实地拍摄或真人经历。

JSON 字段：

```json
{
  "run_id": "本轮批次",
  "video": "实际成片绝对路径",
  "short_title": "地方还在，旧日难回",
  "description": "根据本轮内容创作的描述，标明 AI 创作场景",
  "hashtags": ["旧时光", "物是人非", "怀旧", "时光对照"],
  "settings": {
    "location": "不显示位置",
    "collection": "旧时光",
    "link": null,
    "activity": "不参与活动",
    "schedule": "不定时",
    "original_requested": true,
    "ai_label": "含AI生成内容"
  },
  "publish_status": "awaiting_manual_publish"
}
```

这些设置来自用户截图。“声明原创”按用户意图列为勾选，实际提交时需满足平台要求（包括所用音乐）；未核验不得声称已获原创资格。短标题、话题数量与字数如平台有提示，以实际页面为准。视频号页面显示发表成功前，不能把 `publish_status` 改成 published。Codex 定时运行触发后出片，平台端仍使用“不定时”。

加载 `$telegram-notify`，先 `status`，若已 ready：

1. 发一条完成消息，包含短标题、组数、时长、批次、本地成片路径、需手动发布及本次文案。事件键 `time-echo:<run_id>:complete`，正文存为 `telegram-complete.txt`。
2. 发本轮 MP4，说明存为 `telegram-video.txt`，事件键 `time-echo:<run_id>:video`。超限保留本机文件并说明原因。
3. 将每次脚本返回的状态/消息编号写入本轮 `notification-receipts.json`。发送失败与视频制作状态分开；下次仅处理待通知事项，不重新出片。若某条已经发送，重试复用原正文及事件键。

尚未配置通知时，仍准备全部发布资料，在 Codex 交付本地文件并说明 Telegram 未接通。不要把“资料已准备”说成“已发到手机”或“视频号已发布”。

## 卡点通知

保存失败/断点后，发送简短原因和需要用户采取的一步操作，事件键 `time-echo:<run_id>:blocked:<原因短码>`。相同原因未变化不重复发；原因改变才产生新事件。开机、网络、额度和工具仍决定任务是否能运行；若 Codex 本身无法启动或运行被中断，本技能没有独立后台进程，不能保证发出提醒。没有可靠回执就在当前任务中说明。

其他网站在允许访问时若需要扫码，可将实际二维码作为文件发送到已绑定本人私聊，说明用途及有效期，再等待实际登录状态；不要制作虚假二维码、转发给第三人或把扫码本身视为发布成功。本次视频号因站点限制不执行该分支。
