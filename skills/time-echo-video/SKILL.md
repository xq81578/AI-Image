# 时光对照视频

## 工作位置与工具

本技能服务于 `D:/AI创作生图项目`，先以该目录为工作区，阅读项目 `AGENTS.md`。

本技能的视频号发布唯一入口为第 7 步的固定 `social_upload_adapter.py` 命令，Chrome 启动、登录判断、网页操作与结果核验均由脚本负责。不得另用 `cua_repl` 等浏览器工具打开视频号、探测可访问性、检查登录、截图或手工发布，也不得以核验历史阻塞为由增加浏览器预检。遇到限制或指令冲突时先说明来源及正式入口是否已执行，不自行改道；未执行脚本不能报告为脚本失败。此约束仅针对本技能，详见 [发布入口约束](references/publishing.md#发布入口约束)。

用 `C:/Python313/python.exe codex_video.py` 执行下述本地命令；脚本不生成图片、不判断审美、不访问模型服务。
由当前 Codex 统筹全部选题和最终验收；每个制作子智能体独立负责本组提示词、真实看图和返工决策。图片仅使用内置 `image_gen`；不使用北海、第三方或 OpenAI API/SDK，不需要 API Key，也不自动改用其他平台。
加载 imagegen 技能。制作采用“组间并行、组内串行”：每组一个制作子智能体，组内每次只允许一个 pending，旧照通过后才能生成今照；每张生成后立即保存并查看。并发角色、容量门槛和委派接口见 [组间并发制作](references/parallel.md)。
如果当前定时运行没有内置生图工具，记录阻塞并通知用户，不能假装脚本可以代替工具出图。
手动启动完整出片任务时，在 `begin` 前按 [恢复守护](references/recovery.md) 为当前任务建立临时 heartbeat；由 heartbeat 或其他重复自动化唤醒时复用现有调度，不创建嵌套守护。守护只负责在整个 Codex 轮次意外结束后再次唤醒同一任务，不能绕过模型容量、额度或权限限制。

## 每轮目标

- 只输出 1 条真实生成的 MP4，随机 5 或 6 组新旧照片。一次调用持续完成整轮，而非每轮只做一组。
- 旧照在上、今照在下，1080×1920、30fps，每组 4 秒、转场 0.6 秒，从项目 `bgm` 随机配乐，保持现有成品形式。
- 新年由 `begin` 固定为当年或前一年；旧年在策划时随题材确定并写入 `plan.old_year`，须至少相隔十年。默认选 2000 年以后；只有年代质感可信且至少有两个可靠地点连续线索时才用 1980、1990 年代。重试不改年份，换题可随新场景重新确定。今照变化强度须按实际跨度、材料、气候及停用、失管或拆除路径校准，不能给不同跨度统一套用清场、裂缝和荒草。
- 旧照按“当年原片成像 → 冲印与保存 → 现代手机翻拍”三层设计，分别审核纸内年代画质和纸张物理层次。遮住纸边、手指和年份后，纸内仍须在普通预览尺寸呈现与年代相符的细节损失及现场成像缺陷，不能靠白框、泛黄磨边或看不见的细微噪点通过。现代手机只能把纸面拍清楚，不能恢复当年未记录的景物微纹理；手指遮挡与接触阴影、纸边厚度或微弯、独立纸面受光须让人看出正在翻拍一张实物照片。禁止现代高清场景套旧纸边或对整张成品统一模糊做旧，具体见 [旧照与视觉审核](references/creative-review.md)。
- 今照采用普通手机后置主摄 1×、正常对焦、未经修图的随手拍 JPEG 观感：主结构自然清楚，石材、木材、墙面与草叶各有可信的摄影材质，按现场光线保留亮暗差、暗部细节损失和克制色彩。弃用反差由功能与结构变化支撑，不把裂纹、苔藓和木纹写成满画面都需突出的装饰纹理；不以强 HDR、过度锐化、全图柔化、涂抹、统一压暗或冷灰滤镜补救，具体见 [今照与视觉审核](references/creative-review.md)。
- 题材只围绕中国农村。每组都须让观看者在不依赖年份和文案时，第一眼看出同一乡土空间已从生活运行转为长期停用、失管、荒废或显著空心化；强反差来自真实的功能退出、维护中断和自然演替，不靠灾难废墟、冷灰滤镜或当天清场。今照主体与背景中所有可见人工建筑和设施一律退出使用，采用长期封闭、弃置失修、自然侵入、拆除后空壳或原址残迹；不允许继续居住、经营、正常维护、翻新或改作。悲凉感来自空间不再被需要和照料，各处须有具体弃用后果，避免整轮重复同一种破墙荒草。
- 近景主体沿用按时间跨度、材料和失管路径呈现荒废的现有方式，不强制整体坍塌。室内可搬且可使用、出售或回收的桌椅、柜子、镜子与设备默认已带走、卖掉或回收；只按实际固定方式保留难拆部分、墙印、锚孔或断管，不把整套陈列留在原位一起做旧，具体见 [可变内容与审核](references/creative-review.md)。
- 时间推演须覆盖主体、外围房屋与可见环境，统一采用弃用方向，不再让模型判断是否继续使用。旧照内部可见的房屋、电线杆、线路、棚架、院落、道路及其他人工设施，逐项明确停用、弃置、失修、拆除或残迹；不默认保留原有数量、位置和完整轮廓，不新增仍在使用的替代建筑或设施。中远景及门窗外可辨认的房屋必须消失、明显荒废或倒塌；拆除或倒塌后可只留少量残墙、墙基与瓦砾，保留屋体则须在普通预览尺寸看出大尺度荒废后果，不能只封门、轻微变旧或局部缺瓦。稳定的山体、水系和地形可保留；破损程度仍须符合年份、材料和气候，不能变成灾难废墟。
- 默认出片后清理本轮工作素材，保留视频、轻量预览、选题、提示词、审核和历史记录。`codex-video.json` 的 `keep_images` 可保留素材；不删除内置工具自身保存的原图。

## 运行与恢复

1. `python codex_video.py begin`：在文件锁内检查占用和环境，创建或恢复批次并取得统筹执行权。记下 `run_id`、`folder` 和返回的统筹 `execution.token`，后续统筹修改命令都带 `--token <统筹凭证>`；身份自动取当前 `CODEX_THREAD_ID`。返回 `busy` 时只查看状态并报告占用，不能写本批提示词或审核文件、调用生图、标记失败、发本批通知或另建批次。只有通过 [执行权核验与接管](references/execution.md#执行权核验与接管) 确认原任务及其已授权子智能体都已停止，才能接管。取得执行权后再 `history` 阅读近期主题；每个项目只启用一个出片定时任务。
2. 持有执行权后阅读 `manifest.json`：复用已经通过的图片和所有固定参数；委派状态位于各 `pairs[i].worker`，统筹占用仍位于 `execution.json`。如果制作状态为 `done`，读取 `publish-status` 并直接进入第 7 步恢复发布，不重做视频；如果状态为 `rendered`，直接检查成片并 `finish`；`finishing` 表示清理中断，复用已保存的成片审核再次 `finish`。编码失败只重新 `render`。如果图片已返回但请求仍 `pending`，先由统筹用自己的有效统筹 token 从当前任务上一轮的 `imageGeneration` 工具结果找回对应本地路径、看图后对原 attempt 执行 `record` 或 `fail`；不能先换 worker、不能新增 `attempt` 或重复生图。同一提示词因工具入口错误而重试仍属于原请求，不再次执行 `attempt`。只有工具明确失败或核实不到任何返回图片时才以 `fail` 标记中断，不能无记录地重复调用。
3. 统筹先按本轮实际组数完成全部策划并逐组通过 `plan` 保存；计划必须包含 2–4 个认址锚点、`first_glance_contrast`、`long_term_neglect` 及三类可见变化，具体约束见 [外围时间推演与审核](references/creative-review.md)。全部 `plan` 保存后，按组数一次创建全部制作子智能体；先让每个子智能体只报告真实 `CODEX_THREAD_ID`、canonical agent name 和 `image_gen` 可用性，所有子智能体 `ready` 前禁止任何实际生图。容量不足时保存明确阻塞并报告实际名额，不能静默改成较少 worker 排队。
4. 所有子智能体 `ready` 后，统筹对每个未完成组执行一次 `delegate`，取得独立组凭证，再逐个 `followup_task` 发开工指令。统筹凭证不发给子智能体；子智能体只用自己的真实身份和本组凭证调用 `plan`（仅换题时保存新计划）、`attempt`、内置生图、看图、`record`、`fail`、`replace`。子智能体只写本组提示词、审核和素材，不执行 `begin`、`takeover`、`release`、heartbeat、`render`、`finish`、通知或发布，也不逐步回报制作细节。同组最多一个 pending，今照依赖本组合格旧照；不同组可同时 pending。具体委派接口、目录隔离和总预算见 [组间并发制作](references/parallel.md)。
5. 每张都用视觉工具查看实际像素，填写审核 JSON，再以 `record` 复制图片并登记。旧照按 creative-review.md 分别检查“纸内年代感”和“翻拍物理层次”，在 `observations` 分项记录实际证据；纸内仍像当代高清照片或纸张只靠边框成立时必须返工。今照先在普通预览尺寸与旧照并看，再检查完整像素，单独核对随手拍成像并在 `observations` 记录真实材质、锐度、曝光与色彩；油画笔触、蜡质涂抹、不同材料呈现相似碎块纹理、过锐、暗部普遍提亮或草木鲜艳发光时，`realism=false`、`passed=false`，不能以变暗或变柔代替摄影质感通过；审核必须包含 `first_glance_contrast`、`long_term_neglect` 两项检查，以及非空的 `first_glance_evidence`、`long_term_neglect_evidence`。不能只根据工具成功、提示词、计划文字或图像尺寸判合格；`same_place` 和 `loss` 不能替代强反差与长期失管。今照若看起来只是人物器物撤走、刚清空、关门、整洁仓房或正常设备间，维护中断只藏在小角落，缺少三类变化中的任一类，持久变化少于两项，或叙事只存在于文案，必须判为不通过并定向返工。可搬陈设仍成套留在原位、仅加灰尘或腐朽时，`object_change=false`、`passed=false`。还须独立核对中远景与门窗外的房屋、院落和环境，在 `observations` 记录外围核对、在 `visible_changes` 记录实际外围变化；无可见外围、自然地形稳定或远景细节不可辨时如实说明。可见人工建筑设施仍在正常使用、翻新、改作，或只是轻微变旧而看不出弃用后果时，`time_change=false`、`abandonment=false`、`passed=false`，不能凭主体反差通过。审核未通过就针对具体区域重写提示词并再次 `attempt`，不是原提示词盲重试。
6. 所有组通过后 `render`；查看输出视频提取的 `preview.jpg`，并抽查第一组、最后一组及转场附近的视频帧，检查年份、顺序、构图、转场和无黑屏。脚本已检查音轨存在、尺寸、时长和帧率；没听音乐不能声称听过。填写成片审核 JSON 后 `finish`。
7. 按 [references/publishing.md](references/publishing.md) 准备并登记本轮发布资料，使用 `$telegram-notify` 发送成品，然后执行固定发布脚本 `D:/AI创作生图项目/.venv-social/Scripts/python.exe D:/AI创作生图项目/social_upload_adapter.py --run <批次> --token <执行凭证>`。该脚本连接 `打开视频号.bat` 启动的持久 Chrome，在同一页面完成登录、上传和结果核验；若跳到 `login.html`，脚本截取实际二维码并通过 Telegram 发给本人，等待网页登录成功后自动续跑；已登录时直接上传视频、填写固定设置、登记提交意图并只点击一次“发表”。脚本结束时只断开自动化连接，不主动关闭 Chrome。正常发布不再由 Codex逐项判断或操作网页。缺少明确成功提示时，脚本直接在同一窗口进入作品列表核对；找到匹配作品才登记 published，找不到才返回 `UNCERTAIN_SUBMISSION`，此时禁止再次运行提交。脚本返回 `PAGE_CHANGED`、`FORM_CONTROL_NOT_FOUND` 等阻塞状态时保留进度并报告，不自行改用其他浏览器。发布结论以平台证据为准，通知失败不重做视频或重复发布。完成时用简体中文给出视频链接、组数和时长。发布及通知均完成并登记 delivered，或保存阻塞并发出通知后，执行 `release --run <批次> --token <执行凭证> --reason <停止原因>` 释放占用；`finish`、`block` 本身不会释放。尚有未登记生图请求时先确认结果或实际中断，不能为释放而将仍在运行的请求标记失败。释放后按 [恢复守护](references/recovery.md) 停用本轮临时 heartbeat；若停用失败，报告其名称和状态，但不得因此重复发布。

命令与文件结构见 [references/execution.md](references/execution.md)，选题及看图必读 [references/creative-review.md](references/creative-review.md)。

## 返工边界

默认每张最多生成 3 次（初次加 2 次修正），同一位置最多试 3 个选题，整轮最多 36 次调用，实际限制来自批次创建时保存的配置。失败请求也计数。
同一组多次不合格，使用 `replace` 保存失败原因后换题，继续完成固定组数；不得用重复照片填数或把未通过图片放进视频。
遇到限流/额度耗尽，登记请求失败，`block` 保存原因后结束，不轮询刷请求、不重建批次重置预算、不切换 API。下一次定时唤醒先恢复批次；达到本轮总预算或换题上限时需明确报告并等待用户调整。
其他临时工具错误最多重试一次。同一个 `attempt` 创建后，修正错误路径或重新提交完全相同的生图请求不创建第二条本地请求记录；只有已把上一请求登记为失败或拒绝、准备发起新的模型生成时，才再次执行 `attempt`。图片工具耗时较长不等于失败，不因等待而重复发起请求。保存阻塞后按 publishing.md 通过 Telegram 提醒用户；当前工具不可用但仍可执行本机通知脚本时可以发送，本轮完全无法运行时不能承诺通知必达。

## 定时任务

用户尚未指定时间时，只交付技能与 [schedule-prompt.md](schedule-prompt.md)，不自行启用时间表。
用户给出时间/间隔后，使用 Codex `automation_update` 创建或更新任务，先查已有任务避免重复；一般使用当前任务的 heartbeat，明确针对本机项目运行。不要使用操作系统计划任务或网站 API 代替 Codex 定时任务。
时区以用户设置为准；当前项目用户使用北京时间。电脑需保持开机、联网，Codex 可运行，本机任务还受可用工具、额度和权限约束。首次真正的定时运行需核验内置生图可用，交互试跑不能代替定时运行验证。
周期出片自动化本身已能再次唤醒工作流，不为每次执行另建恢复 heartbeat；其提示词必须要求先恢复未完成批次，并在未完成且没有实质变化时保持安静。手动任务使用的临时恢复 heartbeat 与周期出片任务不是一回事，具体生命周期见 [恢复守护](references/recovery.md)。
