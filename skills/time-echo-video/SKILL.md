# 时光对照视频

## 工作位置与工具

本技能服务于 `D:/AI创作生图项目`，先以该目录为工作区，阅读项目 `AGENTS.md`。
用 `C:/Python313/python.exe codex_video.py` 执行下述本地命令；脚本不生成图片、不判断审美、不访问模型服务。
由当前 Codex 负责选题、提示词、真实看图和返工决策。图片仅使用内置 `image_gen`；不使用北海、第三方或 OpenAI API/SDK，不需要 API Key，也不自动改用其他平台。
加载 imagegen 技能。单张单次、串行生图；每张生成后立即保存到项目并查看，不在同一轮另派生图代理。
如果当前定时运行没有内置生图工具，记录阻塞并通知用户，不能假装脚本可以代替工具出图。

## 每轮目标

- 只输出 1 条真实生成的 MP4，随机 5 或 6 组新旧照片。一次调用持续完成整轮，而非每轮只做一组。
- 旧照在上、今照在下，1080×1920、30fps，每组 4 秒、转场 0.6 秒，从项目 `bgm` 随机配乐，保持现有成品形式。
- 年份由 `begin` 固定：旧年不早于 2000，新年为当年或前一年，以十年以上跨度为主，重试、换题不能改变本组年份。
- 题材可跨农村、小镇、校园、城市、亲情、邻里、宠物、日常职业与生活空间。核心是具体生活失去后的共鸣，避免固定地点轮换和空泛鸡汤。
- 默认出片后清理本轮工作素材，保留视频、轻量预览、选题、提示词、审核和历史记录。`codex-video.json` 的 `keep_images` 可保留素材；不删除内置工具自身保存的原图。

## 运行与恢复

1. `python codex_video.py begin`：检查工具、音乐、中文字体，创建批次或返回未完成批次。记下 `run_id` 和 `folder`。随后 `history` 阅读近期主题。每个项目只配置一个出片定时任务，不同时手动运行另一批；命令有文件锁、未完成批次复用和待处理请求互斥。
2. 阅读 `manifest.json`：复用已经通过的图片和所有固定参数。如果状态为 `rendered`，直接检查成片并 `finish`；`finishing` 表示清理中断，复用已保存的成片审核再次 `finish`。编码失败只重新 `render`。如果图片已返回但请求仍 `pending`，优先找回本次工具结果再登记；确实无法恢复时以 `fail` 标记中断，不能无记录地重复调用。
3. 每组策划后通过 `plan` 保存。先完成旧照并看图审核，再根据**实际旧照**中的锚点和可变元素拟定今照提示词；不可只凭文字想象画面。
4. 每次调用内置生图前，先把完整提示词存成 UTF-8 文本，并执行 `attempt`，记录返回的请求 `id`。实际生图提示词与记录保持一致。今照以本组已通过的旧照为参考；本地参考图必须已用 `view_image` 查看，再传工具支持的本地引用参数。没有本地路径时按内置工具文档使用最近图片引用。
5. 每张都用视觉工具查看实际像素，填写审核 JSON，再以 `record` 复制图片并登记。不能只根据工具成功、提示词或图像尺寸判合格。审核未通过就针对原因重写提示词并再次 `attempt`，不是原提示词盲重试。
6. 所有组通过后 `render`；查看输出视频提取的 `preview.jpg`，并抽查第一组、最后一组及转场附近的视频帧，检查年份、顺序、构图、转场和无黑屏。脚本已检查音轨存在、尺寸、时长和帧率；没听音乐不能声称听过。填写成片审核 JSON 后 `finish`。
7. 按 [references/publishing.md](references/publishing.md) 准备本轮视频号标题、描述和发布设置，使用 `$telegram-notify` 发送成品与通知；目前由用户手动发布视频号。通知失败保留成果，不能重新出片或声称已发布。完成时用简体中文给出视频链接、组数和时长。后台无变化时保持安静，只在完成、失败或需要用户处理时通知；交互试跑可按当前会话要求报告进度。

命令与文件结构见 [references/execution.md](references/execution.md)，选题及看图必读 [references/creative-review.md](references/creative-review.md)。

## 返工边界

默认每张最多生成 3 次（初次加 2 次修正），同一位置最多试 3 个选题，整轮最多 36 次调用，实际限制来自批次创建时保存的配置。失败请求也计数。
同一组多次不合格，使用 `replace` 保存失败原因后换题，继续完成固定组数；不得用重复照片填数或把未通过图片放进视频。
遇到限流/额度耗尽，登记请求失败，`block` 保存原因后结束，不轮询刷请求、不重建批次重置预算、不切换 API。下一次定时唤醒先恢复批次；达到本轮总预算或换题上限时需明确报告并等待用户调整。
其他临时工具错误最多重试一次，保留两次请求记录。图片工具耗时较长不等于失败，不因等待而重复发起请求。保存阻塞后按 publishing.md 通过 Telegram 提醒用户；当前工具不可用但仍可执行本机通知脚本时可以发送，本轮完全无法运行时不能承诺通知必达。

## 定时任务

用户尚未指定时间时，只交付技能与 [schedule-prompt.md](schedule-prompt.md)，不自行启用时间表。
用户给出时间/间隔后，使用 Codex `automation_update` 创建或更新任务，先查已有任务避免重复；一般使用当前任务的 heartbeat，明确针对本机项目运行。不要使用操作系统计划任务或网站 API 代替 Codex 定时任务。
时区以用户设置为准；当前项目用户使用北京时间。电脑需保持开机、联网，Codex 可运行，本机任务还受可用工具、额度和权限约束。首次真正的定时运行需核验内置生图可用，交互试跑不能代替定时运行验证。
