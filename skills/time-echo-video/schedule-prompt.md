使用 `$time-echo-video`，在 `D:/AI创作生图项目` 执行一轮时光对照视频制作。先读取技能、项目约定及 `references/parallel.md`、`references/recovery.md`，并完整遵守 `creative-review.md` 与 `publishing.md` 的质量和发布约束；再由统筹执行 `begin` 取得本轮执行权；所有统筹修改命令带统筹 `--token`。返回 `busy` 时按 `execution.md` 同时核实统筹和已登记子智能体，仍运行、等待工具或状态未知就报告占用并结束，不修改该批、不发通知、不另建批次；仅确认全部已停止后接管。已有未完成制作或发布时从原批次继续，优先找回实际工具结果，不重复生图。

每轮只创建一批次并交付一条视频，随机 5 或 6 组。统筹先按技能完成全部组策划并逐组保存 `plan`，再按实际组数一次创建全部制作子智能体；每个子智能体先只报告真实 `CODEX_THREAD_ID`、canonical agent name 和 `image_gen` 可用性。全部 `ready` 前禁止任何实际生图；宿主名额不足时保存明确阻塞并报告实际名额，不静默退成 2 或 3 个 worker 排队，也不承诺六倍提速。全部 ready 后，统筹对每个未完成组执行 `delegate --run <批次> --pair N --worker <子真实CODEX_THREAD_ID> --agent <collaboration canonical name> --token <统筹凭证>`，再逐个 `followup_task` 一次发开工指令；不要把统筹凭证发给子智能体。

每个子智能体固定负责一组，使用自己的真实身份和组 token 独立完成提示词、旧照生成及真实审核、基于实际旧照的今照生成及审核、定向返工或换题；只写本组提示词、审核和素材，并用现有 `plan`（仅换题时保存替代计划）、`attempt`、`record`、`fail`、`replace` 登记。组内旧照→今照串行，同组最多一个 `pending`，不同组可同时 `pending`；总调用上限仍是整轮共用 36 次，不是每个子智能体各 36 次。子智能体不执行 `begin`、`takeover`、`release`、heartbeat、`render`、`finish`、Telegram 通知或发布，也不逐步回报制作细节。统筹等待各组终态后总体验收，按组编号 `render`、`finish`，继续 `$telegram-notify`，并由统筹按 `publishing.md` 使用默认浏览器全程发布：读取 `ego-browser` 技能，复用登录状态，合并已知操作、按需局部读取，统一核对后登记 ready/submitting 并只发表一次，以平台证据登记 published；结果不明只核验、不重复提交。不运行旧发布脚本，浏览器工具不可用或需要登录时保存进度并通知。恢复时先核实所有子及其工具，旧授权失效后只为未完成组重新委派；本地锁 `busy` 且 `execution` 为空只有限重试同一命令，不重复计数或生图。未完成且状态无实质变化时保持安静。
